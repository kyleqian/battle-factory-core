# `AI_CV_Curse` live receipt — real-ROM verification of the three-roll DEF ladder vs the Ghost HP gate

Bounded SIDE-lane worker session, 2026-08-08, Battle Scene OFF oracle. This
receipt live-verifies `AI_CV_Curse` (`data/battle_ai_scripts.s:1870-1892`,
`EFFECT_CURSE`, 18 Level-50 Factory rental carriers) against the real ROM. It
is the first live check of a **multi-draw** CV handler's roll count and roll
order: the non-Ghost path has three `if_random_less_than 128` sites, so draw
parity — the failure mode this whole port exists to prevent — is exactly what
the reach/control pair discriminates.

## 1. The gate, from the real source

```
AI_CV_Curse:
	get_user_type1
	if_equal TYPE_GHOST, AI_CV_Curse4
	get_user_type2
	if_equal TYPE_GHOST, AI_CV_Curse4
	if_stat_level_more_than AI_USER, STAT_DEF, 9, AI_CV_Curse_End
	if_random_less_than 128, AI_CV_Curse2
	score +1
AI_CV_Curse2:
	if_stat_level_more_than AI_USER, STAT_DEF, 7, AI_CV_Curse_End
	if_random_less_than 128, AI_CV_Curse3
	score +1
AI_CV_Curse3:
	if_stat_level_more_than AI_USER, STAT_DEF, DEFAULT_STAT_STAGE, AI_CV_Curse_End
	if_random_less_than 128, AI_CV_Curse_End
	score +1
	goto AI_CV_Curse_End
AI_CV_Curse4:
	if_hp_more_than AI_USER, 80, AI_CV_Curse_End
	score -1
AI_CV_Curse_End:
	end
```

The split is on the **AI user's own type** — it needs no staged transient
state at all, only a different attacker species chosen at fixture build time:

- **Non-Ghost user:** falls into the three-DEF-band ladder. At the default
  DEF stage (6) all three `if_stat_level_more_than` gates (9, 7, 6) fall
  through, so **all three `if_random_less_than 128` sites are reached**. Each
  site draws once and applies `+1` on a roll ≥ 128 (the `<128` jump skips the
  `score +1`). Score is `+0..+3`, draws are exactly 3.
- **Ghost user:** jumps straight to `Curse4` — **zero draws** — scoring 0 at
  HP > 80% (`if_hp_more_than 80` exits) or −1 below it.

The port (`src/engine/factoryAiCheckViability.ts:4853-4898`) models exactly
this: the Ghost branch reads only HP (`hpPercent > 80 ? 0 : -1`), the
non-Ghost branch walks the three bands with a shared `roll()` helper that draws
one RNG per site and scores `+1` on a non-jump, with the DEF bands gating the
chain (DEF 10-12 stops before roll 1, DEF 8-9 after roll 1, DEF 7 after roll
2). Both branches write `funcResult` via `typeChainFuncResultAfter`.

**Discriminating input chosen for this receipt: the attacker's own typing.** A
fresh switch-in has DEF stage 6 and full HP, so the two rows differ in **both**
score and draw count: control = 3 rolls (+1..+3), reach = 0 rolls (0).

## 2. Reach/control fixture pair

The recipe's twin-fixture shape (cf. the chargeup receipt
`docs/factory-ai-cv-live-receipts-chargeup.md` and the counter pair §34.3 of
`docs/factory-ai-checkviability-ground-truth.md`): a level-5 Magikarp relay
(Splash ×4) is KO'd by the player's four-slot Vital Throw (priority −1, so the
relay always acts first), then the tested mon switches in fresh at full HP with
`[Curse, Splash, Splash, Splash]`. The only difference between the twins is the
AI user's species/typing, both genuine Level-50 Frontier rentals:

- **control** (`mechanic-factory-ai-cv-curse-control-off.json`): AI user
  **Snorlax** (`FRONTIER_MON_SNORLAX_2`, pure Normal). Non-Ghost → the
  three-roll ladder at default DEF stage. Decision = setup 4 + curse 3 + tie 1
  = **8 draws**.
- **reach** (`mechanic-factory-ai-cv-curse-reach-off.json`): AI user
  **Dusclops** (`FRONTIER_MON_DUSCLOPS_4`, pure Ghost). Ghost → Curse4, zero
  rolls; switches in at full HP (115/115) so `if_hp_more_than 80` exits with
  score 0. Decision = setup 4 + tie 1 = **5 draws**.

Both fixtures use `overrides.parties` (complete parties, so the stock ROM
derives types/ability/stats and runs entry hooks itself): player Vaporeon
[Vital Throw ×4], opponent = Magikarp Lv 5 relay, Snorlax/Dusclops
[Curse, Splash ×3], Bulbasaur filler. Same `[A, wait 30, ×52 (A, wait 18)]`
mash cadence as the sibling pairs; `trainerId 222`, `challengeNum 7`,
streak-derived mask 7 (all three scoring passes). Curse's `AI_CBM_Curse` body
(`AI_CheckBadMove`) is the same dual-stat gate as `AI_CBM_BulkUp` (own ATK −10
/ DEF −8), which at neutral stages draws nothing and scores 0; Curse and Splash
have no `AI_TryToFaint` entry and Splash's CV is a plain zero. So the **whole
observable difference between the rows is the Curse CV handler's own three
rolls**.

**The draw parity evidence is the point of this receipt.** Both control rows
show the ROM consuming exactly the three-roll CV footprint: decision transition
triple `1 + 4 + 4` (battle-call draw, 4-draw per-slot setup, then 4 = curse
rolls 3 + tie 1) = **8 draws**, and the engine's `draws.length` is 8 with
exactly three `curse-roll-*` draws. Both reach rows show `1 + 4 + 1` = **5
draws** with zero curse-roll draws. The roll outcomes are visible in each
control row (roll values mod 256 with their jump/`+1` polarity), so a future
port that drew these sites in a different order — or a different number of
times — fails the pin regardless of the final score.

Both control rows scored **+2** (rolls `{20,161,225}` and `{83,165,246}`: two
of three ≥ 128), pushing Curse to 102 and beating Splash — the AI genuinely
chose Curse over Splash twice. The reach rows are a genuine 4-way tie
(`bestMoveSlots` `[0,1,2,3]`) at 100 broken by the decision RNG onto Curse
(seed 1) and Splash slot 3 (seed 99) — the strongest proof that the Ghost
branch's 0 really reached the score.

Decision-window frames: control setup/tail at **f713/f715** (both seeds),
reach at **f728/f730**; the AI user switches in at ~f597 and executes the
chosen move (PP delta) at f786-788. Note the control/reach start RNG values
for a given seed are **identical** (`3894234654` / `1656372911`): the
pre-decision RNG stream is species-independent, so the whole observable
divergence is exactly the CV handler's own roll count — the cleanest possible
attribution.

## 4. Verdict

**MATCH 4/4.** The real ROM runs `AI_CV_Curse`'s three-roll ladder for the
non-Ghost user and the zero-roll Ghost HP gate exactly as the source and
today's port model them. Control consumed 8 decision draws (3 from the CV
handler, each visible and in order) and scored +2 in both seeds; reach consumed
5 decision draws (0 from the CV handler) and scored 0 at full HP. The engine
reproduced every PP-selected slot, draw count, roll outcome, and RNG endpoint.
No `src/engine/` change was needed.
