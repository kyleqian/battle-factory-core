# Battle Factory terminal-endpoint evidence

This dossier records the two remaining Stage-8 endpoint branches from the
pinned pret source. It is deliberately source/data evidence, not an attempt
to fake live UI acceptance or a replacement for the required dense Battle
Scene OFF traces. The reproducible artifact is
`src/data/gen/factory-ending-policy.json`, generated by
`tools/extract/extract-factory-ending-policy.ts` and integrity-tested in
`tests/factoryEndingPolicy.test.ts`.

## Loss ending

`BattleFactoryBattleRoom/scripts.inc:74-90` calls `DoSpecialTrainerBattle`.
Only result `1` branches to `DefeatedOpponent`; every other result falls
through to `WarpToLobbyLost`. That branch sets `CHALLENGE_STATUS_LOST` (4) and
warps singles to the Factory lobby at `(4,8)`. It does **not** increment the
battle counter, Factory win streak, or swap count.

On the lobby's next frame, status 4 selects `LostChallenge`
(`BattleFactoryLobby/scripts.inc:15-20,65-75`): lock, print the return/save
message, check the air-show side effect, `LoadPlayerParty`, clear the active
Factory-streak bit, `factory_save 0`, play/wait the save sound, then enter the
shared optional record-battle prompt. The visible message is source-extracted
in the JSON artifact. No bespoke Battle Factory loss-summary screen exists in
this path.

## Seventh-win / round summary ending

After a win, `BattleFactoryBattleRoom/scripts.inc:92-111` first offers a
rental-swap count increment. `SetBattleFactoryData` only persists that count
if `sPerformedRentalSwap` is true, and clears the flag (`battle_factory.c:
243-266`). The common frontier increment then advances the Factory win streak
unless it already equals 9999 (`frontier_util.c:2111-2157`). Finally the map
script increments `FRONTIER_DATA_BATTLE_NUM`; value 7 selects status
`CHALLENGE_STATUS_WON` (3) and the same lobby warp.

The lobby's status-3 route (`BattleFactoryLobby/scripts.inc:40-63`) is the
round-summary UI: it locks, chooses the normal seven-wins congratulation or
the Factory Head variant, prints the BP award text, calls `frontier_givepoints`
and its `MSGBOX_GETPOINTS` result, then restores the personal party and saves
before the optional record prompt. For a first Level-50 singles round the
source table awards 3 BP; the extractor preserves all 30 Factory-singles rows,
the 10-BP Frontier Brain bonus, and the 9999 cap.

## Assets and remaining oracle work

Both endings reuse the Factory lobby field map, attendant/NPC object graphics,
ordinary field message box, normal font, palette fade, and save/message audio;
there is no source-defined dedicated ending bitmap or static results screen to
harvest. Reusing the existing field/map/message assets is therefore the right
implementation path, but pixel acceptance remains unclaimed here.

The precise remaining OFF probes are:

1. Stage a battle result into the loss script handoff, capture every dynamic
   frame from battle teardown through the lobby's return/save message and its
   first input-ready state; RAM-check status, battle number, active-streak flag,
   and party restoration.
2. Stage battle number 6 with a win, capture every dynamic frame from the
   terminal battle handoff through the lobby congratulations, BP result,
   party restore/save, and record prompt; RAM-check battle number 7, win
   streak, awarded/capped BP, and post-save challenge status.

These need controlled script/RAM staging or an approved deterministic
scenario; replaying six prior battles is neither required nor evidence of the
endpoint mechanism.
