## §0. The two machines this audit must not conflate

Fainting in Emerald is *two* separate state machines that both have to run before a replacement acts:

* **The in-script faint** — `Cmd_tryfaintmon` (`battle_script_commands.c:2965`), executed *inside* the acting move's own Battle Script by the Battle Script VM. It only sets `HITMARKER_FAINTED(battler)`, pushes `BattleScript_FaintTarget`/`_FaintAttacker` (cry, faint anim, `cleareffectsonfaint`, "*X* fainted!"), and optionally splices Destiny Bond / Grudge in front. **It chooses no replacement and ends no battle.** Its `printstring STRINGID_TARGETFAINTED` ends in the `\p` prompt code, so on the real ROM the controller parks in `CompleteOnInactiveTextPrinter` until a button press (PROGRESS 1402 / ISSUES #129's post-mortem). **Any receipt proposed in this doc therefore appends A pulses past every prompt** — a trace that ends on a faint message has observed nothing after it.
* **The out-of-script fainted-actions machine** — `HandleFaintedMonActions` (`battle_util.c:1894-1971`), run by the C main loop, *not* by the VM. It is the one that runs `BattleScript_GiveExp`, `BattleScript_HandleFaintedMon` (which is where `checkteamslost` decides `gBattleOutcome`), the forced-switch dance, and the state-6 Intimidate/Trace/item/Forecast sweep.

`HandleFaintedMonActions` has exactly **two** callers in the whole tree (verified `grep -rn` over `$REF/src`):

| caller | source | when |
| --- | --- | --- |
| `HandleAction_TryFinish` | `battle_util.c:638-645` | end of every *action* — the `B_ACTION_TRY_FINISH` slot in `gActionsByTurnOrder`. Loops until it returns FALSE, then zeroes `faintedActionsState` and sets `B_ACTION_FINISHED`. |
| `BattleTurnPassed` step 4 | `battle_main.c:3968-3970` | end of every *turn*, **ungated on `gBattleOutcome`** (`docs/end-turn-ordering-audit-2026-08-25.md` §1). Then zeroes `faintedActionsState` unconditionally. |

Port: `src/engine/battleScriptFaintedActionsOrchestration.ts:340` `runBattleScriptFaintedActionsOrchestration` is the single entry for both, plus `:592` `resumeBattleScriptFaintedActionsAfterPlayerChoice` for the player-pause resume. End-of-action seam: `factoryBattleScriptFullTurnDecision.ts:2704` and `factoryBattleScriptTerminalDecision.ts:816`. End-of-turn seam: `battleEndTurnOrchestration.ts:2543` / `:2684` / `:2894` / `:2910`.

**The port collapses the C re-entrant machine into synchronous calls.** Per the brief, shape is not judged; ORDER and OUTCOME are.

## §2. `HandleFaintedMonActions` (`battle_util.c:1894-1971`) state by state

**Cursor semantics.** Two bytes in `gBattleStruct` (`include/battle.h:373-374`): `faintedActionsState` (0..7) and `faintedActionsBattlerId`. Both survive across `BattleScriptExecute` yields; `FAINTED_ACTIONS_MAX_CASE` is `7` (`battle_util.c:1892`). Iteration is by **battler index 0→`gBattlersCount`**, i.e. player-slot-first — **never** turn order. Both callers zero `faintedActionsState` only after the function finally returns FALSE (`battle_util.c:642`, `battle_main.c:3970`), never `faintedActionsBattlerId`.

**The load-bearing singles fact this audit re-derived.** `HasNoMonsToSwitch` (`battle_util.c:2279-2286`) opens with `if (!(gBattleTypeFlags & BATTLE_TYPE_DOUBLE)) return FALSE;` — **in singles it is unconditionally FALSE**. Grepped over the whole `$REF/src` tree: its only callers are `HandleFaintedMonActions` case 0 (`:1907`) and `Cmd_openpartyscreen` (`:4887`, `:4913`, `:4935`, `:4956`, `:4977`, `:5041`, `:5057`, `:5106`). This single fact decides rows 2.1, 3.6 and 3.7 below.

> Note: the port module's own header comment (`battleScriptFaintedActionsOrchestration.ts:17-22`) justifies skipping case 0 with "`HasNoMonsToSwitch` is always true for them". That is the **opposite** of the source's singles behaviour (always *false*). The conclusion — case 0 is a provable no-op — still holds, but for the reason in row 2.1, not the one the comment gives. Comment-only; no code consequence. PAPERCUT-adjacent, not a divergence.

### §4a. Finding 1 in detail (the one DIVERGENT of this audit)

**Claim.** When a **replacement's ability is Intimidate or Trace**, the port's `Cmd_switchineffects` exits early and never performs two clears that source performs on that exact path.

**Both sides re-opened.**
* Source: `battle_script_commands.c:5226` (`gHitMarker &= ~HITMARKER_FAINTED(gActiveBattler);`, unconditional) and `:5268` (`gSideStatuses[GetBattlerSide(gActiveBattler)] &= ~SIDE_STATUS_SPIKES_DAMAGED;`, inside the `if (!AbilityBattleEffects(ABILITYEFFECT_ON_SWITCHIN,…) && !ItemBattleEffects(ITEMEFFECT_ON_SWITCH_IN,…))` body at `:5264-5265`).
* Port: `src/engine/battleScriptSwitchinOpcode.ts:1224` (Intimidate) and `:1236` (Trace) both `return transitionBattleScriptCommand(context, {kind:"advance"}, {rulesContext: {...nextRules, battlers}})` — carrying **neither** `hitMarker: hitMarkerWithoutFainted` (computed at `:1141`, applied only at `:1173` and `:1277`) **nor** the `sideStatuses[side] &= ~SIDE_STATUS_SPIKES_DAMAGED` performed at `:1270-1271`.

**Why the source really does take that body** (this is the step that refutes the obvious "but Intimidate is an effect, so source skips the body too"): `AbilityBattleEffects`'s `ABILITYEFFECT_ON_SWITCHIN` cases for `ABILITY_INTIMIDATE` (`battle_util.c:2559-2565`) and `ABILITY_TRACE` (`battle_util.c:2575-2581`) set only `gStatuses3[battler]` and a `gSpecialStatuses` bit and then `break` — **there is no `effect++` in either case**, so the function returns 0. (Contrast `ABILITY_DRIZZLE`/`SAND_STREAM`/`DROUGHT`/`FORECAST`, which all do `effect++` and push a callback.) That is also exactly why `HandleFaintedMonActions` state 6 has to run `ABILITYEFFECT_INTIMIDATE1`/`ABILITYEFFECT_TRACE` afterwards at all: the switch-in only *flags* them.

**Constants re-derived:** `SIDE_STATUS_SPIKES_DAMAGED = (1 << 9)` (`include/constants/battle.h:217`) — the port's `:72` matches. `HITMARKER_FAINTED(b) = gBitTable[b] << 28` (`include/constants/battle.h:205`) — the port's `1 << (28 + battler)` matches.

**Tree-wide grep of both symbols** (`grep -rn` over `$REF/src` + `$REF/include`, and `rg` over `src/`):
* `SIDE_STATUS_SPIKES_DAMAGED` — source writers: `:2978` (`Cmd_tryfaintmon` mode≠0, on the faint branch), `:5236` (set), `:5268` (clear). Port: `battleScriptHitChainOpcode.ts:4323` (clear), `battleScriptSwitchinOpcode.ts:1160` (set), `:1271` (clear). **The `:1271`/`:5268` pair is the only clear on a survivor's path.** Nothing else in either tree resets it — it is not part of `TurnValuesCleanUp`.
* `HITMARKER_FAINTED` — with row 3.7 proved (`HasNoMonsToSwitch` is always FALSE in singles, so `Cmd_openpartyscreen:5110`'s clear is dead), `:5226` is the **only** site in a singles battle that clears a battler's faint bit.

**Observable consequence (the SPIKES_DAMAGED half — concrete and reachable).** Put Spikes on one side, then faint two mons on that side, giving the *first* replacement Intimidate (or Trace):
1. Replacement B lands. `SPIKES_DAMAGED` clear → Spikes fire → B takes `maxHP/((5-layers)*2)` and survives → cursor returns to `switchineffects` with `SPIKES_DAMAGED` **set**.
2. Pass 2: the Intimidate branch advances. **Port leaves `SPIKES_DAMAGED` set for the rest of the battle; source clears it.**
3. B later faints. Replacement C lands. Source: `SPIKES_DAMAGED` is clear → **C takes Spikes damage**. Port: `SPIKES_DAMAGED` is still set → **C takes zero Spikes damage**.

With 1 layer that is `maxHP/8`; the two runs then differ in C's HP for the whole rest of the battle, and diverge outright whenever that chip would have been lethal or would have crossed a Pinch-Berry / Endeavor / Flail threshold. The same handler serves `switchineffects BS_ATTACKER`, so a *voluntary* switch into an Intimidate/Trace mon under Spikes has the identical effect (the voluntary path is a sibling audit's scope; only noted).

**Proposed receipt** (`mechanicLab`, `overrides.parties`, Battle Scene OFF, stock ROM):
* Player side, three complete legal L50 mons: slot 0 a fragile non-Flying/non-Levitate lead; **slot 1 a non-Flying/non-Levitate `ABILITY_INTIMIDATE` holder** (e.g. GYARADOS is Flying — use TAUROS or MAWILE, whose only ability is Intimidate, so `abilitySlot` is unambiguous); slot 2 another non-Flying/non-Levitate mon whose maxHP makes `maxHP/8` a distinctive number.
* Opponent side, three mons; give all four move slots of the active the SAME move so the Factory AI has exactly one legal choice, and make that move `MOVE_SPIKES` for the first turn — then swap to a strong attacking set for the KO turns. (Neither side may be given transient state; the Spikes layer must be laid by a real `MOVE_SPIKES` use.)
* Trace variant: replace the Intimidate holder with a `ABILITY_TRACE` holder (GARDEVOIR/KIRLIA/RALTS `abilitySlot` 1) facing an opponent with a non-zero ability.
* Trace/instrument: watch `gSideStatuses[0]` bit 9 and `gBattleMons[0].hp` across the two switch-ins.
* **The trace MUST append A pulses past every `\p` prompt.** Every faint message (`STRINGID_TARGETFAINTED`/`STRINGID_ATTACKERFAINTED`), `STRINGID_SWITCHINMON`, and the party-menu confirmation blocks the controller until a button press — a window that ends on the first faint message has observed nothing at all (PROGRESS 1402 / ISSUES #129).

**Observable consequence (the `HITMARKER_FAINTED` half — CLOSED this session, and the more severe of the two).** The stale bit is never cleared again: `BattleTurnPassed`'s own hitmarker resets (`battle_main.c:3975-3978`) clear only `HITMARKER_NO_ATTACKSTRING`, `HITMARKER_UNABLE_TO_USE_MOVE`, `HITMARKER_PLAYER_FAINTED` and `HITMARKER_PASSIVE_HP_UPDATE`, and `HandleAction_ActionFinished`/`HandleAction_NothingIsFainted`'s masks (`battle_util.c:648-668`) do not include the faint bits either. The reachable reader is `Cmd_moveend` itself: `battle_script_commands.c:4416-4417` `if (!(gHitMarker & HITMARKER_FAINTED(gBattlerTarget))) gLastHitBy[gBattlerTarget] = gBattlerAttacker;` — and the port reproduces that gate exactly at `src/engine/battleScriptRulesContext.ts:1537-1544` (`const targetFaintedMask = ((1 << target) << 28) >>> 0; if ((hitMarker & targetFaintedMask) === 0) { lastHitBy = … }`). So once a replacement lands with Intimidate or Trace, **`lastHitBy` for that battler is frozen at `0xff` for the whole rest of the battle** — every subsequent hit on it silently skips the write. `lastHitBy` is not bookkeeping: its readers are `src/engine/factoryAiSwitchPolicy.ts:500-507` (source `battle_ai_switch_items.c:342` `if (gLastHitBy[gActiveBattler] == 0xFF) return FALSE;` and `:407` `battlerIn1 = gLastHitBy[gActiveBattler];`) and `src/engine/battleScriptTypeChangeOpcode.ts:140` (Conversion 2). **Concretely:** give the OPPONENT's second mon Intimidate. Source `:4444`'s `MOVEEND_MIRROR_MOVE` gate reads the same bit, so the `lastTakenMove` buffers diverge alongside it. This is the same one-line remedy as the Spikes half: both clears live in the same two `return`s.

Source really reaches that body for Intimidate and Trace because `battle_util.c:2559-2565` and `battle_util.c:2575-2581` set only `gStatuses3[battler]` and a `gSpecialStatuses` bit with **no `effect++`**, so `AbilityBattleEffects` returns 0.
* Port: `src/engine/battleScriptSwitchinOpcode.ts:1224` (Intimidate) and `src/engine/battleScriptSwitchinOpcode.ts:1236` (Trace) both `return … {kind:"advance"}` carrying neither clear; the clears live only at `src/engine/battleScriptSwitchinOpcode.ts:1173` (Spikes branch) and `src/engine/battleScriptSwitchinOpcode.ts:1270-1281` (fall-through tail).
* **Observable consequence:** with Spikes on a side, the *first* replacement on that side having Intimidate or Trace leaves `SIDE_STATUS_SPIKES_DAMAGED` set for the rest of the battle (its only other writers are the set at `:5236`/`:1160` and `Cmd_tryfaintmon` mode≠0's faint-branch clear at `:2978`/`:4323` — verified by tree-wide grep on both sides). The **second** replacement on that side therefore takes **zero Spikes damage** in the port and `maxHP/((5 - layers) * 2)` (⌊·⌋, min 1) on the ROM — `maxHP/8` at one layer. Every subsequent HP-threshold effect (Pinch Berries, Endeavor, Flail/Reversal power, a lethal chip) diverges from there. The same handler serves `switchineffects BS_ATTACKER`, so a *voluntary* switch into an Intimidate/Trace mon under Spikes has the identical effect.
* **Second observable consequence (more severe, needs no Spikes):** the same two `return`s also skip source's unconditional `gHitMarker &= ~HITMARKER_FAINTED(gActiveBattler)` (`battle_script_commands.c:5226`). Nothing clears that bit again — `BattleTurnPassed`'s resets (`battle_main.c:3975-3978`) and `HandleAction_*`'s masks (`battle_util.c:648-668`) omit the faint bits, and `Cmd_openpartyscreen`'s other clear is dead in singles (row 3.7). `Cmd_moveend` reads it every move: `battle_script_commands.c:4416-4417` gates `gLastHitBy[gBattlerTarget] = gBattlerAttacker` on the bit being clear, and the port ports that gate verbatim at `src/engine/battleScriptRulesContext.ts:1537-1544`. So a replacement with Intimidate/Trace has its `lastHitBy` **frozen at `0xff` for the rest of the battle**. With the OPPONENT's replacement holding Intimidate, `src/engine/factoryAiSwitchPolicy.ts:500-507` (source `battle_ai_switch_items.c:342`, `:407`) then short-circuits and the port's AI **never considers switching again**, where the ROM's would — a whole-action divergence. Source `:4444`'s `MOVEEND_MIRROR_MOVE` gate reads the same bit and diverges alongside it.
* **Fixture that would expose it on the stock ROM** (`mechanicLab`, `overrides.parties`, Battle Scene OFF): player slot 0 a fragile non-Flying/non-Levitate lead; **slot 1 a non-Flying/non-Levitate Intimidate holder whose species has Intimidate as its only ability** (MAWILE or TAUROS — unambiguous `abilitySlot`); slot 2 another grounded mon with a distinctive `maxHP/8`.
