# Helping Hand / `B_SCR_OP_TRYSETHELPINGHAND` evidence

This is a SIDE-lane source-and-oracle checkpoint only. It adds no production interpreter, controller, animation, or rendering code.

`trysethelpinghand` is opcode `0xD1`: one opcode byte followed by a four-byte little-endian relocation pointer. It **first** assigns `gBattlerTarget` to the attacker’s partner position (`BATTLE_PARTNER` flips `BIT_FLANK`), with no guard around that assignment. It succeeds only when the battle is doubles, that position is not absent, and both the attacker and selected partner have a clear `ProtectStruct.helpingHand` bit. Success writes the bit on the **partner**, not the attacker, then advances five bytes. Every failure instead loads the pointer at `PC + 1`. The command has zero local RNG calls.

`EFFECT_HELPING_HAND` orders `attackcanceler → attackstring → ppreduce → trysethelpinghand BattleScript_ButItFailed`; therefore even the honest singles failure spends PP first. Success alone continues through animation, `STRINGID_PKMNREADYTOHELP`, wait, and `MoveEnd`; the failure branch is the ordinary `BattleScript_ButItFailed` result-message path. The source move record is normal/user-targeted/PP 20/priority +5. `GetWhoStrikesFirst` compares chosen move priority before speed, so in a successful doubles turn the helper normally sets its partner-owned bit before a lower-priority partner attacks.

Both `Cmd_damagecalc` and `AI_CalcDmg` read the *acting attacker* bit and multiply its calculated damage by `15 / 10`. Normal `TurnValuesCleanUp(FALSE)` byte-clears every active `ProtectStruct` only after end-turn effects, faint processing, and Wish/Perish handling. `FaintClearSetData` also writes the active bit false. `SwitchInClearSetData` does not preserve any `ProtectStruct` member; ordinary switch routes therefore cannot carry an old turn’s bit past the normal cleanup. These are source facts—not inferred from the singles receipt.
