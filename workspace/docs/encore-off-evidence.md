# Encore / `B_SCR_OP_TRYSETENCORE` evidence

This SIDE-lane checkpoint adds no engine, controller, rendering, or animation code.

`trysetencore` is opcode `0xA4`, a byte plus a four-byte failure pointer ([macro](../reference/pokeemerald/asm/macros/battle_script.inc#L868-L871), [dispatch](../reference/pokeemerald/src/battle_script_commands.c#L495)). `Cmd_trysetencore` searches the target's slots for `gLastMoves[target]`; Struggle, Encore, and Mirror Move are invalid; a pre-existing `encoredMove`, no matching slot, or zero PP takes the pointer. Success writes the target's `DisableStruct` move/id position and then `encoreTimer` plus start value as `(Random() & 3) + 3` ([handler](../reference/pokeemerald/src/battle_script_commands.c#L8017-L8046), [fields](../reference/pokeemerald/include/battle.h#L70-L102), [Random](../reference/pokeemerald/src/random.c#L11-L16)).

The effect order is attack canceler, accuracy, attack string, PP reduction, setter, success message, and MoveEnd; failed setters therefore already spent Encore PP ([script](../reference/pokeemerald/data/battle_scripts_1.s#L1227-L1237)). The setter owns the timer draw; the preceding accuracy check can own separate RNG. The target's active selection replaces its choice with `encoredMove`/position; `CheckMoveLimitations` blocks every nonmatching slot while the timer is live ([selection](../reference/pokeemerald/src/battle_main.c#L4192-L4219), [execution](../reference/pokeemerald/src/battle_util.c#L112-L128), [limitations](../reference/pokeemerald/src/battle_util.c#L1082-L1139)). Expiry decrements at `ENDTURN_ENCORE`, ends on zero or encored-slot PP zero, and runs `BattleScript_EncoredNoMore` ([end turn](../reference/pokeemerald/src/battle_util.c#L1719-L1736), [message script](../reference/pokeemerald/data/battle_scripts_1.s#L3374-L3377)). Switch/faint zero the DisableStruct; Baton Pass zeroes it then restores only its enumerated non-Encore fields ([switch](../reference/pokeemerald/src/battle_main.c#L3152-L3225), [faint](../reference/pokeemerald/src/battle_main.c#L3264-L3318)).

[`mechanic-encore-minun-chansey-off.json`](../tools/battle-lab/mechanic-encore-minun-chansey-off.json) uses two complete legal three-mon parties. Chansey has four stock Tackle slots, so normal AI is constrained without injecting a choice. A real first Tackle stages the last move; Minun then succeeds with Encore, repeats it for pointer-path failure, and lets Chansey act through the timer window. Every relied-on frame is captured on a 25-frame grid. Two manifests are byte-identical: `329676e3ac0cfb47f22254562dc910a2203d4531040d6392c0bb65030fe8bba2`; scenario SHA-256: `d35ca78f86033779aaa8b369f34b16e169a23d5e286720ad728ba41baa356024`.

- Frame 325: Chansey has already spent one Tackle PP (`[35,34,35,35]`), staging a real last-used move.
- Frame 725: Minun is executing Encore (`227`), and its PP is `5 → 4`; this is the public success receipt.
- Frame 875: Chansey executes Tackle (`33`) and its own PP becomes `[34,34,35,35]`.
- Frame 1350: repeated Encore is still current move `227`, with Minun PP `4 → 3` and no Chansey mutation: the public result is consistent with the already-encored pointer path after PP reduction.
- Frame 1500: Chansey again executes Tackle and spends its own PP (`[33,34,35,35]`).

The manifest cannot decode `gLastMoves`, any `DisableStruct` timer/move field, PC/result flags, or choice slot. Its four identical Chansey moves deliberately make post-expiry action identity ambiguous. Those branches—including the exact 3–6 timer draw, early expiry on slot rewrite/PP zero, Disable/Torment composition, and cleanup—remain source claims, not oracle claims.
