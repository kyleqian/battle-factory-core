Evidence/design only; new files, no tracked file edited. Format follows `docs/visual-randomness-prep.md`.
Source = `reference/pokeemerald` (paths relative to it). Production paths are repo-relative `src/...`.
Drafted fixtures (NOT consumed by any test yet): `tools/integration/fixtures/next-<move>-<side>.json`
(`<side>` = attacker side), regenerated by `tools/integration/nextAdaptersDraft.py`.

## 0. Cross-cutting findings

1. **All five accepted renderers are species-pair gated** and throw otherwise: Dizzy Punch Spinda<->Onix
   (`src/engine/battleScene.ts:20055-20080`), Scary Face Rhyhorn<->Shuckle (`:33124-33148`), Glare
   Dunsparce<->Shuckle (`:33266-33299`), Soft Boiled Chansey self-target with Onix (`:46441-46460`), Teeter Dance
   Spinda attacker/Onix target (`:43043+`). Config *numbers* can be made species-general (below), but a live
   adapter that is "ordinary-play ready" also needs the art lookups generalised; until then a live adapter only works for
   the accepted staged species, like the current ones. Decide that scope before wiring `liveMoveAnimationDuration`
   (`src/engine/liveMoveAnimation.ts:160`), which returning non-null for these ids would make other species throw.
2. **Personality is not on the live path.** The displayed field battler (`BattleCommandFieldBattler`,
   built `src/engine/battleCommandPresentation.ts:316-345`) reads `partyMember.personality` only to derive gender
   (`:339`); `BattleResolutionDisplayedField` (`src/engine/battleResolutionPresentation.ts:255`) and
   `BattleMoveAnimationRequest` carry none. Fields that do exist: `BattleScriptRulesBattlerState.personality`
   (`src/engine/battleScriptRulesContext.ts:365-366`, parsed `:2445`; "Transform deliberately leaves it unchanged") and
   party `personality` (`:555`, parsed `:1950`); `fieldBattler` already asserts active == party personality
   (`battleCommandPresentation.ts:355-358`). So the exact source is the attacker's `battlers[...]`/party record at the
   point the live view is built, threaded into the live seam as a new field (not today's request shape).
3. **Shadow rows** (ISSUES #142; `LIVE_MOVE_OPPONENT_SHADOW_ROW`, `src/engine/liveMoveAnimation.ts:93-106`,
   currently has none of 135/137/146/184/298). Rule from `docs/issue142-shadow-rows.md`: `shadowRow = activationFrame -
   windowStart + ageOffset`; offset 0 => row 0 (draw the elevated-opponent shadow on live age 0). A negative row
   means the window starts after activation: not in window, do **not** add the id to that map.
4. Probe CLI shape for all five probes is `<scenario> <output.json> <rgb-dir>`, which is what
   `verifyLiveAdapterFramebuffer` passes (no extra probe args, no start-frame argument). Dizzy/Scary/Glare/Teeter/Soft Boiled
   probes emit `frames[]` with `frame`+`sha256`, so the harness window filter works.

## 3. Soft Boiled renderer gap

Accepted renderer (`battleScene.ts:46441-46500`):
* Gate requires attacker AND target both CHANSEY on the same side (`:46451-46460`): fine for the staged case.
* The non-attacker mon is drawn from hard-coded Onix: player case `onixCorner={x:145,y:10}` with `onixFrontSprite`
  (`:46487-46490`), opponent case `ONIX_MATERIALIZE_CORNER` with `onixBackSprite`; Chansey uses `softBoiledArt.chansey{Back,Front}` (`:46472-46475`).
* Source: `Move_SOFT_BOILED` (`data/battle_anim_scripts.s:7685-7706`) does `monbg ANIM_ATK_PARTNER`; the target is the user, so
  `gBattleAnimTarget == gBattleAnimAttacker` and the heal stars (`HealingEffect2`, `:10059-10069`, `ANIM_TARGET`, `gHealingBlueStarSpriteTemplate`
  through `AnimSpriteOnMonPos`, `src/battle_anim_mons.c:1515-1530`, arg3 = 0 => `respectMonPicOffsets` TRUE) land on `InitSpritePosToAnimTarget(..., TRUE)` =
  `X_2 / Y_PIC_OFFSET` of the attacker. So **`healingCenter` = `liveBattlerAnchors(attackerSide).picOffsetPoint`** (player Chansey (72,99), opponent (176,49), matching the accepted values).
* What the renderer must use instead of the Onix constants: the other-side battler's species, art and corner from the
  displayed field (`createBattleCommandFieldArtView(field)[otherSide]` + `battleCommandFieldSpriteOrigin(art, side)`, the same path `liveBattlerAnchors`
  uses, `liveMoveAnimation.ts:140-150`); i.e. take the second battler from the typed field, not from `config.target` (which is the attacker for this move). The
  `SceneOnSoftBoiledConfig` has no field for it (`sceneOnPresentation.ts:1755-1763`); either add a `bystander` battler or let the live view draw it under the
  scene as other adapters' "target" backgrounds do. Chansey art itself is also move-asset-specific (the BG-layer monbg copy).
* Request wiring gap: `liveMoveAnimation.ts:365-368` builds `target` as the opposite side; the harness list
  `SELF_TARGET_MOVES` (`liveAdapterFramebuffer.ts:57`) lacks SOFT_BOILED, so the drafted fixture cannot pass until that set (an existing file) gets `SOFT_BOILED`.
* `fieldProfile` HP: player 297/325 (opponent attacker 296/325), measured in the dense state; the heal itself is gameplay HP after the body.

## 4. Eye coordinates (Scary Face, Glare): computable for any species

All inputs are the species pic height and the per-side picture point already produced by `liveBattlerAnchors`.
Verified numerically against the accepted fixtures with the production function (DUNSPARCE/SHUCKLE/RHYHORN pairs).

* **Scary Face `attackerEyeCenter`** = `InitSpritePosToAnimAttacker(sprite, TRUE)` (`src/battle_anim_mons.c:833-847`,
  `AnimEyeSparkle` `battle_anim_effects_2.c:3510-3514`, script args -16/+16, -8 at `battle_anim_scripts.s:7780-7781`) = attacker
  `picOffsetPoint`. Fixtures: Rhyhorn player (72,100), opponent (176,49); `liveBattlerAnchors` gives exactly (72,100)/(176,49). The reducer adds the
  +-16 / -8 arg offsets itself (`scaryFace.ts:130-160`); the config holds the un-offset point.
* **Glare** (`AnimTask_GlareEyeDots`, `battle_anim_effects_3.c:3989-4015`):
  * `eyeDotStart.x = attacker X_2 +/- HEIGHT/4` (+ for player attacker, - for opponent), `eyeDotStart.y = attacker Y_PIC_OFFSET - HEIGHT/4`, with
    `HEIGHT = GET_MON_COORDS_HEIGHT(coords->size)` (`GetBattlerSpriteCoordAttr`, `battle_anim_mons.c:2151-2266`; back table for player, front for opponent; the
    pretty `height` in `src/data/gen/mon-pic-coords.json`, e.g. Dunsparce back 40, front 32). This is **not** `LiveBattlerAnchors.pictureHeight`
    (`64-2*yOffset`, 34/46 for these); a new `pictureCoordHeight` would have to be read from `mon-pic-coords.json`.
    Check: player Dunsparce pic (72,103), h=40 => (82,93) as fixture; opponent Dunsparce pic (176,57), h=32 => (168,49) as fixture.
  * `eyeDotEnd` = target `picOffsetPoint` ((176,49) / (72,99) in the fixtures).
  * `attackerEyeCenter` = attacker `picOffsetPoint` + (0,-8) (sparkle `arg1=-8`, `battle_anim_scripts.s:2897-2898`): (72,95)/(176,49). (Scary Face's config omits the -8; Glare's includes it, per `glare.ts:331-332` which only adds the x offset.)
* Species coverage: any species in the production art tables; transformed/Unown cases follow `GetBattlerSpriteCoordAttr` (transformSpecies), not modelled.
