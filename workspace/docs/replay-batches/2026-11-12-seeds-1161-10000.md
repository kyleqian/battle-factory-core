# Real-ROM replay of seeds 1161..10000 (Mac, Scene OFF, 2026-11-12)

Bulk batch run by the replay-batch session (`worker/replay-batch-mac`) with `tools/replay-batch/`. Not diagnosed, nothing fixed here: this file counts and sorts.
Per-seed data: `2026-11-12-seeds-1161-10000.json` (same folder). Terms and signature names follow `docs/gameplay-parity-audit-2026-11-12.md` sections 5 to 8.

## In plain words

- 8,840 new battles were played by the engine and replayed on the real game (seeds 1161 to 10000). 182 of them are Frontier Brain battles that the lab cannot set up yet, so they were not played.
- On the engine as it was when the batch started (`a86909863e`): **7,828 matched, 830 did not match, 182 could not run.**
- The fix lane's engine (`680b907f3`) was then run on all 8,658 battles that can be played: **8,612 match to the end, 41 are too long for the replay's frame limit (no mismatch in the states compared), 5 cannot be set up by the lab, and 0 mismatch.**
- Of the 830 mismatches on the old engine, **785 (94.6 %) match on the fix lane's engine**, 41 are the too-long ones, 4 are lab setup failures. No mismatch is left over.
- Of the 7,828 that matched on the old engine, 7,827 still match. One (seed 5633) is now refused by the lab-setup check (see below).
- The 64 regression seeds (handoff 0d) all still match on `680b907f3`: **64 of 64**.
- Nine seeds failed in one 72-second window of the fixed-engine run (0 states matched) and matched when driven again. That was a one-off glitch on the Mac, not the engine. Details below.

### Lab staging failures (5, `rc=13`)

`replay` stopped with "the lab staging already played a turn" (the check from the replay-tool fix 3), and the same on a second drive. Seeds: **3623, 5736** (known to the fix lane), **8075, 9188** (new), **5633**.
Seed 5633 matched all of its states on the old engine (the old tool did not record the last moves, so it could not see this). Its setup shows last moves `[25, 95]` with both leads at full HP (187/187 and 151/151), so the new check refuses it. The staging race is in the oracle lab (top layer), not the engine.

### One-off glitch on the fixed engine (9 seeds, now counted as match)

Seeds 4777 4781 4782 4783 4784 4794 4796 4797 4812. On the first pass each had **0 states matched** (three also stopped early at a menu) and all nine finished within 72 seconds of each other (19:40:02 to 19:41:14 UTC; 58 seeds finished in the two minutes around that time, 9 of them failed). Driven again with the same engine and command, all nine matched to the end (42/42, 11/11, 27/27, 11/11, 9/9, 30/30, 29/29, 32/32, 40/40). The setup files and the engine output are identical in both passes; the ROM's first recorded `gRngValue` differs (seed 4781: 4046267346 on the first pass, 3580535886 on the second). No cause was looked for. The old-engine batch has no such cluster of 0-matched seeds. If the Mac lane sees a batch of seeds with 0 matched states close together, drive them again before reading anything into them.

## How it was run

```

```
