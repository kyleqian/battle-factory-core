### DIVERGENT summary

#### FINDING 1 — Thief/Covet vs Sticky Hold: the port returns to the *next* opcode where the ROM returns to the *same* one, losing one `Random()` draw (**high — RNG desync for the rest of the battle**)

* **Source** `reference/pokeemerald/src/battle_script_commands.c:2770-2771` — `BattleScriptPushCursor(); gBattlescriptCurrInstr = BattleScript_NoItemSteal;`. `BattleScriptPushCursor` pushes `gBattlescriptCurrInstr` **itself** (`reference/pokeemerald/src/battle_util.c:966-969`), not `+ 1`. `BattleScript_NoItemSteal` ends in `return` (`reference/pokeemerald/data/battle_scripts_1.s:4209-4213`) → `Cmd_return` → `BattleScriptPop` (`battle_util.c:971-974`) → the cursor lands back **on the `seteffectwithchance` opcode**, which re-executes. `:2770` is the only entry into that script in the whole tree (`grep -rn BattleScript_NoItemSteal reference/pokeemerald/src reference/pokeemerald/data`).
* **Port** `src/engine/battleScriptHitChainOpcode.ts:3122-3138` — `transitionBattleScriptCommand(context, {kind: "call", programCounter}, …)`. `"call"` pushes `state.programCounter + 1` (`src/engine/battleScriptMachine.ts:998-1009`). The machine **does** model the source's shape as `"call-current"` (`:1010-1021`); this site simply does not use it.
* **Observable consequence.** On the second execution the byte is 0 (cleared at `:2905` and again at `:2937`), so arm 2's `Random() % 100 < percentChance` is still evaluated — the first conjunct — and only then fails on `&& gBattleCommunication[MOVE_EFFECT_BYTE]`. The stock ROM therefore consumes **two** `seteffectwithchance` rolls on this turn; the port consumes **one**. Every subsequent draw in the battle — the next turn's `Cmd_damagecalc` 85-100 % roll, `Cmd_critcalc`, every secondary-effect roll, and `gRandomTurnNumber` — is shifted by one, so HP numbers diverge from the following turn onward. There is no message difference (both sides print `STRINGID_PKMNSXMADEYINEFFECTIVE` once, and the second pass prints nothing).
* **Fixture that exposes it on the stock ROM.** `mechanicLab` with `overrides.parties`, three complete legal Level-50 mons per side. Player slot 1: `SPECIES_LINOONE` with `MOVE_COVET` in slot 1 (`.effect = EFFECT_THIEF`, `.secondaryEffectChance = 100`, `src/data/battle_moves.h:4462-4472`) and three filler moves. Opponent slot 1: `SPECIES_GULPIN` or `SPECIES_SWALOT` with `abilitySlot` selecting **Sticky Hold**, a non-Enigma, non-mail held item, and **all four move slots the same** damaging move so the Factory AI has one legal choice. `BATTLE_TYPE_FRONTIER` is set, so `ITEM_STEAL_ALLOWED_SPECIAL_BATTLES` short-circuits the two "regular battle" arms (`:2747-2766`) and the Sticky Hold arm at `:2767-2775` is reached. Frame 0 is the turn-1 action menu with the AI already committed; window **turn 2+** so the AI decision is inside the trace; append A pulses past every prompt. Compare the **turn-2** damage number on both sides: the port's is drawn one `Random()` earlier than the ROM's.

#### FINDING 2 — Thrash / Outrage / Petal Dance lock-in: same shape, no `BattleScriptPushCursor` involved — the ROM simply never advances the cursor, and re-runs `seteffectwithchance` (**high — RNG desync on every rampage start; 9 of 882 catalog entries**)

* **Source** `reference/pokeemerald/src/battle_script_commands.c:2851-2862` — the `MOVE_EFFECT_THRASH` success branch writes `STATUS2_MULTIPLETURNS`, `gLockedMoves[gEffectBattler]` and `STATUS2_LOCK_CONFUSE_TURN((Random() & 1) + 2)` and then `break`s **without touching `gBattlescriptCurrInstr`** — the only one of the 24 family-B cases that does so (re-checked case by case across `:2533-2900`). Control falls to `:2905`, which clears the byte and returns; `Cmd_seteffectwithchance` clears it again at `:2937`; the cursor still points at `seteffectwithchance`, which re-executes.
* **Entry path (verified, not assumed).** `BattleScript_EffectRampage` → `BattleScript_EffectRampage2` → `confuseifrepeatingattackends` (`Cmd_confuseifrepeatingattackends`, `battle_script_commands.c:7131-7137`, sets byte `MOVE_EFFECT_THRASH | MOVE_EFFECT_AFFECTS_USER` when not already locked) → `goto BattleScript_HitFromCritCalc`, whose tail runs `seteffectwithchance` (`reference/pokeemerald/data/battle_scripts_1.s`, `BattleScript_HitFromCritCalc` → `BattleScript_HitFromAtkAnimation` → `seteffectwithchance`). `MOVE_THRASH.secondaryEffectChance = 100` (`src/data/battle_moves.h:484-495`), so arm 2 always fires and escalates to `certain` via W7.
* **Port** `src/engine/battleScriptHitChainOpcode.ts:3917-3921` (`applyThrashMoveEffect`, reached from `:3265-3267`) returns `{kind: "advance"}`; `src/engine/battleScriptConfuseifrepeatingattackendsOpcode.ts:31-46` stages the byte exactly as the source does, so the port's path is identical up to this one transition.
* **Observable consequence.** Draw order on the lock-in turn — ROM: (1) `seteffectwithchance` chance roll, (2) `(Random() & 1) + 2` lock duration, (3) **a second `seteffectwithchance` chance roll, wasted**. Port: (1), (2), then advance. The lock duration itself matches (it is drawn before the divergence), so Thrash still rampages the same number of turns; but from the *next* draw onward the two RNG streams are offset by one, so the turn's `tryfaintmon`/`moveend` tail, `gRandomTurnNumber`, and every subsequent damage/crit/secondary roll differ.
* **Fixture that exposes it on the stock ROM.** `mechanicLab` with `overrides.parties`. Player slot 1: any Level-50 rental legal with `MOVE_THRASH` (or `MOVE_OUTRAGE` / `MOVE_PETAL_DANCE` — 2 + 2 + 5 catalog entries) in slot 1, no `STATUS2_LOCK_CONFUSE` staged (staging transient state is forbidden anyway; turn 1 is naturally unlocked). Opponent slot 1: a bulky mon that survives the hit, all four move slots the same move so the AI has one legal choice. Window turn 1 through turn 3; append A pulses past every prompt. The lock-in fires on turn 1; compare the **turn-2** damage number (the ROM's is one `Random()` later than the port's). A second, sharper witness: give the opponent a 30 %-secondary move such as `MOVE_ROCK_SLIDE` (76 catalog entries) and compare whether the flinch procs on turn 2 — a one-draw offset flips it on roughly 30 % of seeds.
