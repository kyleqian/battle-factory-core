# Rollout + Defense Curl residual: diagnosis (S10A side lane, new files only)

## 0. Results

**Verdict: the "constant 6 px field residual" is NOT Curl and NOT the species' geometry. There are three independent causes, and fixing the first two makes all four Curl bodies pixel-exact (0 residual, 2 fresh direct-mGBA runs each).**

Cause 1 explains the "constant from age 0" and the unexplained 6 px; causes 2 and 3 are the real adapter defects hidden under it (with Scene-OFF frames, none of them could be separated, which is why "target idle offset ruled out" and "cause not isolated" both held).

### Fix shape (not applied: new-files-only step)
1. `rollout.ts shakeTaskAtAge`: `amplitude = clamp(floor(power / 12), 1, 16)` with `power` = the request's `gAnimMovePower` (thread `request.power` through the config, e.g. a `movePower` field next to `counter`); keep `ROLLOUT_SHAKE_AMPLITUDES` as the plain-ladder default. This also makes the `defenseCurlPower` table (`rollout.ts:201`) consumed instead of dead.
2. `rollout.ts impactAtAge`: take the centre from the target geometry (`liveBattlerAnchors(target.geometry.side, art)`; ROM values to match: opponent ONIX 42, BLISSEY 46; the player-target constant 88 was only measured for VOLTORB), not the 176/42 and 72/88 constants. **Open:** which anchor field reproduces 42 *and* 46 (`picOffsetPoint`/`spriteCenter`+`yOffset` in `liveBattlerAnchors`, `liveMoveAnimation.ts:313`) was not computed in the time cap; pick it by checking ONIX=42, BLISSEY=46 (and WAILMER, the existing alt fixture), then re-run the accepted plain fixtures (must stay 0).
3. `liveMoveAnimation.ts` case 205: delete the decline (`request.power !== 30 << (counter - 1)`) and the `liveMoveAnimationDuration` power check once 1+2 land; the Curl bodies use the same row counts [167, 167, 161, 153] (all matched at 167/167/161/153 here, power ladder 60..480).
4. Re-generate the Curl fixtures against `tools/battle-lab/rollout-curl-defense-curl-sceneon.json` (their `scenario` field), promote to `fixtures/rollout-live/`. Also fix the Scene-OFF scenario file's profile or stop using it for dense RGB.

Caveat: Defense Curl's fifth body (power 960 -> shake 16) was never reached on the ROM (BLISSEY faints at hit 4), so only counters 1-4 are proven. The Scene-ON batch also still runs the curl `fieldProfile` unchanged (HP 362/362 etc.), which is correct for Scene ON.
