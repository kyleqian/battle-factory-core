* Equal at all 14 ROM bodies (5 + 5 + 4) and all 10 engine hits (two engine geometries x 5): `counter = start - timer` is the **rock** formula (`battle_anim_rock.c:759`, `retVal = rolloutTimerStartValue - rolloutTimer`); the ice formula (`battle_anim_ice.c:1540,1613`) is `start - timer - 1` (0..4). The ROM probe also reads the struct the animation actually uses: `gAnimDisableStructPtr` points at a **buffer copy** made by `BtlController_EmitMoveAnimation(..., &gDisableStructs[gBattlerAttacker], ...)` (`battle_script_commands.c:1787`); its byte `+0x11` equals the live struct's at all 14 bodies (`animPtrCounterRock == counterRock`). So the value is **frozen at the MOVE_ANIMATION event**, after `rolloutdamagecalculation` (`BattleScript_RolloutHit`: `rolloutdamagecalculation` then `BattleScript_HitFromCritCalc`, `battle_scripts_1.s:1603-1606`) decremented it. Engine order is the same: `battleScriptRolloutOpcode.ts:55-61` decrements, `:91-98` writes the start value, then the hit chain emits the event.

The last hit is timer 0, start 5 -> 5 (ROM identical; a miss cancels the timer to 0 and emits **no** MOVE_ANIMATION, so there is nothing to mis-read).
* **Defense Curl cannot be inferred from the power**: hit 1 with Curl has power 60 = hit 2 without. The counter needs its own field (confirmed: ROM `gAnimMovePower` alone is ambiguous).
* **Plumbing (presentation only, no gameplay/RNG touch):** at `battleScriptHitChainOpcode.ts:2285-2308` (the MOVE_ANIMATION event, arguments `[move, animTurn, power, damage, friendship, multihit]`), append a 7th presentation argument (or a sibling field on the request) `rolloutCounter = rulesContext.rolloutTimerStartValues[attacker] - attackerBattler.rolloutTimer` **only when `move === 205`** (ROLLOUT; Ice Ball uses the same struct, move 301). ### 0.2 ENDEAVOR stale power: **TRACKABLE** (four deterministic writers + cross-battle carry; no engine-side randomness)

Endeavor itself never calls it (no `damagecalc`), so its animation request carries whatever was left. **Rule R (W2, measured, 16/16 movesets x 2 AI levels, `tools/integration/rolloutEndeavorAiRule.py`)**: after an AI decision, the register equals the table power of the **last slot** (slot order 0..3) of the AI mon's moveset that has `power > 1` **and** effect not in `sIgnoredPowerfulMoveEffects` (CHECK_BAD_MOVE-only AI, challenge 2-3); with the full flag set (challenge >= 4) it is the last slot with `power >= 2` of **any** effect (TryToFaint's `if_can_faint(considered)` adds the ignored-effect moves, e.g. Explosion 250). Moveset samples `[33,157,98,283]`->40, `[98,157,283,283]`->75, `[157,153,33,283]`->35, `[283,157,98,33]`->35, `[157,98,283,33]`->35, `[33,157,98,153]`->40 (CBM) / **250** (full), `[153,33,98,157]`->75, `[33,98,283,153]`->40 / **250**. The ROM makes dozens of calls per decision (8-31, spread over 2-5 frames), but only the last survives: the engine does **not** need to replay the sequence; one assignment at the end of each AI decision is exact. The value is the *modified* power (attacker = the AI mon, defender = its target, `gDynamicBasePower = 0` so the table power).

The AI burst of turn N+1 happens at the *start* of that turn's command phase; an Endeavor in turn N+1 therefore sees R **unless** a faster mover's damagecalc (W1, or its W3) lands first.

**Persistence / first battle:** the symbol has no other writer or reset (`grep gBattleMovePower reference/pokeemerald/src` = declaration + the `CalculateBaseDamage` writes + the one read), so it is **EWRAM, zero at power-on and carried across battles**. Measured 0 for the whole first battle of the ordinary route (3400 frames, challenge 0). Battle k+1 of a run starts with battle k's last writer, so the engine needs `battleMovePower` in **orchestrator state across battles** (`createBattleScriptRulesContext` defaults `battleMovePower ?? 0`, `battleScriptRulesContext.ts:2678`, i.e. today it restarts at 0 for each battle context; carry it from the previous context at battle creation, `factoryBattleScriptFullTurnDecision.ts:592`). The tests' first Endeavor in a run is 0.

**Where the engine must write (all presentation-only, nothing reads it for gameplay):**
1. W1: already done (`:1636`); additionally let Endeavor's MOVE_ANIMATION emit `rulesContext.battleMovePower` **always** (`:2301` currently falls back to the table power 1 because `battleMovePowerWritten` is cleared at action finish; ROM `Cmd_attackanimation` always passes the register). Keep the table fallback for every other move so no existing consumer changes.
2. W2: at the end of each AI move decision (only when `GetAiScriptsInBattleFactory` flags != 0: challenge >= 2 or Brain) set `battleMovePower` by rule R, using `calculateBaseDamageWithPower(...).movePower` for the chosen slot (`factoryAiTryToFaint.ts:124` already builds the exact inputs).
3. W4: record `movePower` at the confusion self-hit (`battleScriptActionAdmission.ts:2976`, 40) and Future Sight (`battleScriptTrysetfutureattackOpcode.ts:106`).
4. W3: port the TV loop after the player's NVE / "doesn't affect" message (the engine already prints those strings) writing the power of the **last** eligible player slot (the single value is enough: only the last assignment is observable).
5. Cross-battle carry as above.

**Verdict TRACKABLE**, with cost ordering: W1 + persistence (cheap), W2 rule R (cheap, only challenge >= 2), W4 (cheap), **W3 is the one non-trivial port** (needs the effectiveness message hook and the eligibility conditions; without it a *player* Endeavor after an NVE / immune hit is wrong, e.g. 40 vs 75 above). Without W3 the staged first-battle cases (0) and every no-NVE case are exact. The generated-rental seeds of prep10 §2 (58/0 GROVYLE, 52/0 BEEDRILL, 61/0 RATICATE) are all **streak 0 = challenge 0 = AI flags 0**, so W2 never fires on them; the ordinary route equivalent was measured with the canonical battle-1 trace + staged Endeavor (0). **Open:** a seed at streak >= 14 (challenge >= 2) would exercise W2 on an ordinary route; the ROM side is established by the lab rule R only (the lab uses the same `BattleLab` trainer path with the Factory AI flags).

## 1. Method

* `tools/integration/rolloutEndeavorProbe.py <scenario.json|x> <out.json> [--stage=<side>:<move>:<pp>] [--nosentinel]`: per animation body (gAnimScriptActive / sAnimMoveIndex), activation snapshot (`gDisableStructs[b]` byte `+0x11` = `rolloutTimer` (low nibble) / `StartValue` (high nibble), `status2`, `gAnimMovePower`, `gBattleMovePower`, `gDynamicBasePower`, `gAnimDisableStructPtr` and the byte it points to); **value-independent write detection** for `gBattleMovePower` (a write of the same value is a write): each frame is run for real (unperturbed), then replayed from the saved state with a `0xFFFF` sentinel, and if the sentinel was overwritten it is single-stepped to list each `CalculateBaseDamage` entry's LR (named by the nearest ELF text symbol: `Cmd_damagecalc`, `AI_CalcDmg`, `TrySetBattleSeminarShow`). Lab `prepare()` frames are included (labelled `p<k>`; the first AI decision happens there). A first attempt wrote the sentinel into the live run and leaked `0xFFFF` into `gAnimMovePower` through the controller copy: the replay design avoids it.
* `rolloutEndeavorEngine.ts`: the merged full-turn reducer (same API as `tests/factoryBattleScriptRolloutFullTurn.test.ts`) through 5 consecutive Rollout hits, no curl / curl first (first seed >= 325391 with five hits in a row), printing the MOVE_ANIMATION arguments and the rules-context fields.
* `rolloutEndeavorDraft.py`, `rolloutEndeavorAiRule.py`, `rolloutEndeavorAll.sh` (all probes, `xargs -P6`, ~22 s per run), `rolloutEndeavorProbes.sh` (ad hoc).

## 2. Open questions
1. W3 conditions on `gMoveSelectionCursor` / `ShouldCalculateDamage` (Magnitude `powerOverride 10`, Psywave) were read from source, only the plain "all four slots eligible" case was measured; the engine port should be pinned with a two-moveset ROM pair (one including Magnitude).
2. Rule R was measured for first decisions and repeated decisions with fixed movesets; the AI also decides on a forced switch-in and when the AI mon has fewer than 4 moves (empty slots, `move == 0`): not exercised.
3. Pinch-ability (x1.5 at HP <= 1/3) and Water/Mud Sport halving change the *register* but not the table power: not exercised in the AI-order runs (full HP, no abilities). `calculateBaseDamageWithPower` already returns the modified value for the hit chain; the AI port must pass the same attacker ability/HP.
4. Ice Ball (301) shares the Rollout struct and counter plumbing; not probed.
5. A 5th Defense Curl hit was not reached on the ROM (the BLISSEY target faints at hit 4); the engine shows 960 for it, ROM expectation 960 by the doubling rule (`battleScriptRolloutOpcode.ts:99-108`).
